# MacSlim

[English](README.md) · 日本語 · [简体中文](README.zh-CN.md)

アプリのアップデート後に残ったインストーラパッケージ、蓄積したキャッシュ、過去のログを見つけ出し、内容を確認してから整理できるネイティブ macOS クリーンアップツールです。macOS 13 以降に対応し、Apple Silicon と Intel の両方で動作する Universal バイナリを提供します。検証済み環境の詳細は[テスト記録](docs/testing.md)を参照してください。

> 本ドキュメントは **1.1.1-beta.5 プレリリース版** に対応しています。配布パッケージは [GitHub Releases](https://github.com/jayson-sheyue/mac-slim/releases) に実際に掲載されているアセットが基準となります。過去のバージョンとは機能や安全境界が異なります。

[インストールとビルド手順](#インストールと使い方) · [スキャン規則の詳細](#スキャン規則の詳細)

## なぜアプリは使うほど肥大化するのか？まずはディスクを「マンション」に例えてみましょう

Mac のストレージは、あなたが毎日暮らしている家具付きマンションのようなものです。Chrome、WeChat、Cursor、WPS などのアプリは、部屋に入居している住人や、仕事を手伝ってくれる執事にあたります。

入居したばかりの頃、各アプリは小さなスーツケース 1 つしか持っていません。しかし長く暮らすうちに、アップデートの際に開けた段ボール箱、すぐ使えるようにキッチンに出しっぱなしにした食材、過去の修理記録などが少しずつ物置を埋め尽くしていきます。**場所を取っているものがすべてゴミとは限りません。片付けてよいものもあれば、今まさに使っているものや、大切な家財道具も含まれています。**

よくある容量増加の理由は、次の 6 つの生活シーンで理解できます。なぜアプリが大きくなるのかという背景と、MacSlim がどこまでを対象にするかを並べて説明します。

### 1. 自動アップデートの残骸：新しいテレビを設置した後に片付け忘れた段ボール箱

執事はあなたが忙しい合間に、古いテレビと入れ替えるための新しいテレビと緩衝材入りの箱を先に運び込んでおきます。こうしておけば、入れ替えのときにあなたがずっと待っている必要はありません。ところが、アップデートが途中で中断されたり、再試行されたり、後片付けが完了しなかったりすると、梱包箱や展開された一時コピーが部屋の隅に残ってしまうことがあります。

アプリの ShipIt や Sparkle などのアップデータも同様に、インストーラをダウンロード・展開・一時保管します。**MacSlim が主に探すのは、こうした過去の「梱包箱」です。** まずディレクトリ構造と更新日時を確認し、さらに関連アプリや更新プロセスが動作中でないかを照合します。最近のファイルや使用中の項目は保持されます。フォルダ名に「update」と付いているだけで、すぐに捨ててよいと判断することはありません。

### 2. 旧バージョンのフレームワーク：新しい椅子は届いたけれど、古い椅子にもまだ誰か座っているかもしれない

アプリによっては、アップグレード時に新しい部品一式を隣に用意しておき、次回アプリを再起動したタイミングで切り替える仕組みを採っています。作業中の処理を止めないための工夫ですが、古い部品がしばらく残ったり、自動削除されずにそのまま残ったりすることがあります。

しかし、「新しい椅子が隣にある」からといって「古い椅子には誰も座っていない」とは限りません。**MacSlim は規則に一致する旧バージョンのフレームワークを一覧表示し、場所を確認できるようにしますが、自動削除は行いません。** アプリのコード署名や実行方式はそれぞれ異なるため、整理が必要な場合はアプリ自身のアップデート機能または公式の再インストールをご利用ください。

### 3. Web・アプリキャッシュ：キッチンカウンターに並べた調味料や下ごしらえ済みの食材

Web ページを開くたびに一から「買い出し」に行くと時間がかかるため、アプリは画像やスクリプト、オフライン素材を手元に置いて次回すぐ使えるようにします。表示が速くなり通信量も節約でき、オフラインで開けるコンテンツもありますが、数か月前に一度使っただけの「調味料の瓶」がずっとカウンターを占領し続けることにもなります。

MacSlim はこうしたキャッシュ候補を一覧表示しますが、**用途を断定できない未知のキャッシュは初期状態で未選択**になっています。削除すると再ダウンロードが必要になったり、オフラインデータが使えなくなったりする場合があります。また、アカウント情報、パスワード、ブックマークは「家の鍵」や「住所録」のようなものであり、近くの引き出しに入っているからといって一緒に捨ててはいけません。こうした個人データの特徴を検出した場合、MacSlim は対象を保護し、注意案内を表示します。

### 4. AI・オフィスソフトの履歴データ：製本された下書きや業務台帳

チャット履歴、下書き、取り消し履歴、作業状態、コードのスナップショットは、作業の再開や過去の内容の復元に役立ちます。容量は取りますが、台帳が分厚いからといって中身がすべて不要な紙くずだと決めつけることはできません。アプリやバージョンによって保存形式が変わることもあります。

**この領域は MacSlim のクリーンアップ対象外です。** 現在のバージョンでは Cursor の `state.vscdb` の再構築や、AI チャット履歴・各種アプリの履歴データベースの削除は行いません。整理が必要な場合は、各アプリが提供する管理・バックアップ・エクスポート機能を優先して使ってください。

### 5. 開発ツールのダウンロード・ビルド成果物：工事のあとに残った足場と工具小屋

依存パッケージの導入、プログラムのビルド、自動テストの実行では、まず資材をダウンロードして環境を組み立てます。残しておけば次回の作業が速くなりますが、プロジェクトが終わると長い間放置されることもあります。ただし、「キャッシュディレクトリ」にあるからといって不要な鉄くずとは限りません。たとえば Playwright がダウンロードしたブラウザは、テストスイートが現時点で使用している道具かもしれません。

MacSlim は pip、Homebrew、node-gyp などの標準キャッシュ位置にある古いキャッシュを一覧表示し、ユーザーが確認して選択できるようにします。Playwright についてはパッケージ参照を照合し、登録・使用中のバージョンを保持します。**プロジェクトをしばらく開いていないという理由だけで、仮想環境や使用頻度の低いアプリをアンインストールすることはありません。** オフライン環境で作業する前は、必要なダウンロード資材を残しておいてください。

### 6. 診断・クラッシュログ：故障調査のために残されたドライブレコーダー映像

アプリが動作中やエラー発生時にログを残すのは、開発者が原因を調べる手がかりにするためです。障害が起きた直後は非常に重要ですが、長期間たまり続けると無視できない容量になることがあります。

MacSlim は過去のログファイルを識別し、最近更新されたログは保持します。不具合を調査中の場合は、開発者に提出するログを先に確保してください。**古いログであっても、自動的に「不要なログ」になるとは限りません。**

## なぜアプリ開発元は最初から全部きれいに片付けないのか？

多くのアプリには、もともとキャッシュ上限、ログローテーション、アップデート後の回収仕組みが備わっています。それでも中断や異常終了、複数バージョンの併存などすべてのケースを網羅できるわけではなく、開発元は次のバランスを取る必要があります。

- **誤削除の代償の方がはるかに大きい。** 古い箱が 1 つ残っても場所を取るだけですが、箱に紛れていた大切なファイルを捨ててしまうと、ユーザーの作業成果が失われます。
- **速度と空き容量はトレードオフの関係にある。** キャッシュを多めに残せば次回の起動や表示は速くなりますが、消せば再ダウンロードや再ビルドが必要になります。
- **アプリごとの「少しずつ」が、Mac 全体では「山積み」になる。** 1 つのアプリが残す量はわずかでも、多数のアプリが積み重なると目に見える大きさになります。
- **「しばらく触っていない」と「もう使わない」は違う。** あなたが本当にその機能をやめたのか、来週また続きを始めるのかを、アプリ側が正確に判断するのは困難です。

そのため、容量増加を単に「開発元が掃除をサボっているから」と決めつけることはできませんし、すべてのアプリに同じ削除ルールを一律適用することも安全ではありません。

## MacSlim はどのように整理を手伝うのか？

MacSlim は、いきなり捨てるのではなく「まず目録を作ってから確認する整理アシスタント」として動作します。

1. **まず梱包箱と古い記録を探す。** 各アプリがどこにファイルを置いているかを暗記しなくても、更新の残骸・キャッシュ・過去ログを重点的に見つけ出します。
2. **用途と影響をわかりやすく示す。** 期限切れの更新パッケージや過去ログのうち推奨項目は初期状態で選択されますが、未知のキャッシュや開発ツールキャッシュは内容を確認してから手動で選択します。旧バージョンのフレームワークは場所の確認専用です。
3. **標準ではまず「ゴミ箱」へ移動する。** 実行前にファイルの変更有無や関連アプリの稼働状態を再確認し、復元先パスを記録します。ゴミ箱へ移動した段階ではまだ空き容量は増えず、ゴミ箱を空にした時点で回収されます。完全削除には別途確認が必要です。

初めて使うときは、対象アプリを終了し、初期設定のまま推奨項目の影響説明を確認して、まずは少数の項目から試してください。アプリの動作に問題がないことを確認してから、ゴミ箱を空にするかどうかを判断してください。**MacSlim の目的は「何を整理しているのかを把握できるようにすること」であり、毎回何十 GB も空きが増えることや、いかなるクリーンアップも副作用ゼロであることを保証するものではありません。**

## インストールと使い方

一般ユーザーは Python、Node.js、Swift をインストールする必要はありません。[Releases](https://github.com/jayson-sheyue/mac-slim/releases) から対象バージョンの Universal DMG をダウンロードして開き、`MacSlim.app` を「アプリケーション（`/Applications`）」フォルダへドラッグしてください。ローカルビルドの候補パッケージは `dist/` に出力されますが、`dist/` にファイルが存在していても GitHub 上で正式リリース済みであることを意味しません。

インストール後の正規起動パスは `/Applications/MacSlim.app` です。マウントした DMG や別の場所から新しいビルドを開いた場合、インストール済みのアプリへ引き継がれます（未インストールの場合は先にインストールするよう案内されます）。同一の macOS ユーザーアカウントで複数の新しいビルドを同時に起動しても、クリーンアッププロセスは 1 つだけ維持されます。

現在は Ad-hoc 署名を使用しており、Developer ID 署名および Apple 公証（Notarization）はまだ完了していません。ダウンロード後の初回起動時に Gatekeeper によってブロックされる場合があります。配布元を確認した上で、[Apple 公式サポート記事](https://support.apple.com/en-gb/102445)の手順に従い、「システム設定 → プライバシーとセキュリティ」から「このまま開く」を選択してください。システムのセキュリティ保護自体を無効化する必要はありません。

1. **「スキャン開始（Start Scan）」** をクリックします。スキャンとクリーンアップはすべてオフラインで動作します。初回起動時の表示言語は **English** が標準で、上部ツールバーまたは **「設定（Settings）」** から `English`・`日本語`・`中文` をいつでも切り替えられます（スキャン結果はリセットされません）。
2. 判定根拠、影響、ファイルパスを確認します。推奨項目は初期選択されていますが、未知のキャッシュは手動で選択してください。
3. 初期モードは **「ゴミ箱に入れる（Move to Trash）」** です。**「完全削除（Delete Permanently）」** は確認ダイアログが表示され、取り消すことはできません。
4. **「履歴（History）」** から結果の確認や復元ができます。元の場所に新しい同名ファイルがある場合は上書きしません。ゴミ箱を空にした後や、元の親フォルダがなくなった場合は自動復元できません。
5. 権限不足で読み取れない場所がある場合はスキップ通知が表示されます。「検出なし」を「保護領域まで含めてすべてスキャン完了した」と解釈しないでください。保護されたディレクトリをスキャンする必要がある場合は、「システム設定 → プライバシーとセキュリティ → フルディスクアクセス」に MacSlim を追加してください。`root` 権限で実行する必要はありません。

「ゴミ箱に移動済み」はファイルの場所が変わったことを意味し、その時点で利用可能容量が増えるわけではありません。サイズは割り当てブロックに基づく概算であり、APFS のクローン、スナップショット、圧縮、他プロセスの動作によって実際に回収される容量は変動します。

**「停止（Stop）」** をクリックすると後続の項目を止め、現在実行中のファイル操作が完了するまで待機します。すでに完了した移動や削除は自動的には元に戻りません。クリーンアップ実行中は、再スキャンや別のファイル操作を開始できません。

## スキャン規則の詳細

識別ルールはディレクトリ構造、アプリの Bundle ID、ファイルの更新日時に基づいており、特定のアプリ名だけに限定されません。初期設定では直近 14 日以内に変更された項目を保持し、用途を確認できないキャッシュは未選択とします。

## データとコード署名の境界

- インストール済みの `.app` バンドルを変更せず、バイナリアーキテクチャの削減（スリム化）やサードパーティ製アプリの再署名も行いません。旧バージョンのフレームワークを安全に削除できるかどうかはアプリのパッケージング・署名・実行方式に依存し、`Current` が指していないことだけでは削除可能の証明になりません。アプリ公式のアップデートまたは再インストールで対処してください。
- Cursor データベースの再構築、チャット履歴の削除、休眠アプリのアンインストール機能は提供していません。長期間開いていないという理由でアプリ本体やコンテナを削除することはありません。
- アップデート残骸やキャッシュ候補に Cookie、Login Data、Bookmarks、パスワード/キーチェーン、データベースなどの個人データの特徴が含まれる場合は保護し、注意案内を表示します。通常の `Documents`、チャット保存領域、下書きフォルダなどはスキャンしません。ただしサードパーティ独自の保存形式をすべて推測することはできないため、未知のキャッシュは人間による確認が必要です。
- Playwright が現在使用中、または登録済みパッケージから参照されているブラウザは削除しません。Playwright-Go や参照を検証できないランタイムも保持します。未登録パッケージやカスタムブラウザパスを使用している場合は、依存するバージョンを削除しないでください。
- いかなるサードパーティアプリや将来のバージョンに対しても「100% 副作用ゼロ」を約束するものではありません。アプリの更新によってディレクトリの用途が変わる可能性があり、最近変更された項目、シンボリックリンクのリダイレクト、別ボリュームにまたがるパス、スキャン後に変化した項目はスキップされます。

## 設定・アップデート・復元データ

設定と復元記録は `~/Library/Application Support/MacSlim/` に保存されます。1.0 からアップグレードした場合、互換性のある最小サイズ設定は引き継がれますが、廃止されたデータベース再構築・休眠アプリ・カスタム更新フィード設定は無効化されます。旧バージョンの履歴ファイルはディスク上に残りますが、復元可能レコードとしてはインポートされません。

**「設定（Settings）」** では表示言語（`English` / `日本語` / `中文`、初回起動時は `English`）、最小サイズ、保持日数を調整できます。ネットワーク通信は **「アップデートを確認（Check for Updates）」** をクリックしたときのみ行われ、更新元は本プロジェクトの GitHub Release マニフェストに固定されています。ダウンロードされたパッケージはファイルサイズと SHA-256 の検証を通過する必要があり、独立した一時ディレクトリに隔離属性を維持したまま保存され、実行中のアプリを自動的に置き換えることはありません。なお、SHA-256 はファイルの完全性チェックであり、配布元署名や Apple 公証の代わりではありません。

復元記録はゴミ箱へ移動する前に書き込まれ、記録領域が利用できない場合はゴミ箱への移動自体をブロックします。予期せず終了した場合は次回起動時に未完了レコードを照合します。システムのゴミ箱を読み取れない場合は、Finder で手動対応が必要です。アプリによる復元を期待する場合は、`recovery-v1.json` を手動で削除しないでください。診断サマリーにはファイルパス、アクセストークン、生のエラーメッセージは含まれず、自動送信も行われません。

## 開発と検証

ソースからの開発ビルドには、macOS と Swift 6 に対応した Xcode Command Line Tools が必要です。配布アプリの実行自体には開発ツールは不要です。

```sh
./scripts/check.sh
./scripts/build_dmg.sh
./scripts/verify_release.sh
```

- `check.sh` は macOS 13 最小デプロイターゲットの静的型チェックと、隔離された一時ディレクトリ内での実ファイル操作回帰テストを実行します。実際のアプリの終了、本物のゴミ箱の使用、個人データベースへのアクセスは行いません。
- `build_dmg.sh` は `arm64` と `x86_64` の Universal アプリ、DMG、`SHA256SUMS.txt`、`release-manifest.json` を生成し、バージョン、署名、チェックサムを照合します。
- CI は macOS 15（`arm64`・Intel）および macOS 26 のチェックを設定しています。設定ファイルの存在は、未プッシュの変更がリモート実行済みであることを意味しません。
- `--self-check` は起動とバージョン識別のみを確認するものであり、UI 全体、インストール、クリーンアップのテストを代替しません。ユーザー向けの CLI クリーンアップインターフェースはなく、Windows、Linux、またはデスクトップなしのリモートクリーンアップには対応していません。

メンテナがリリースを公開し、ローカルの `/Applications/MacSlim.app` を同期する場合は次のコマンドを使用します。

```sh
./scripts/publish_release.sh --prerelease
# 十分な検証を経た正式版では --stable を使用
```

このスクリプトは、ソースがコミット・プッシュ済みであり、該当コミットの CI が通過していることを要求します。ビルドは 1 回だけ行い、まずドラフト Release にアップロードし、同じ DMG を再ダウンロードしてチェックサムを検証した上で `/Applications/MacSlim.app` へインストールし、ファイルツリー全体・バージョン・ソースコミット・単一実行プロセスを確認してから最後に Release を公開します。中断後の再実行では既存のドラフトアセットを再利用し、再パッケージによる上書きは行いません。メンテナ環境には認証済みの GitHub CLI（`gh`）、ローカルの Python 3、および `/Applications` への書き込み権限が必要です（一般ユーザーには不要です）。

更新前には MacSlim に通常終了を要求し、実行中のタスクがある場合は強制終了せず中断します。Bundle ID を確認した旧アプリやテスト用コピーは圧縮バックアップを作成・検証してから実行可能コピーを除去し、インストール失敗時はロールバックを試みます。バックアップとインストール証跡は `~/Library/Application Support/MacSlim/InstallBackups/` に、過去のビルド成果物は `.build/prior-artifacts/` に保存され、ユーザー設定と復元記録は保持されます。リリース後の成果物検証は `./scripts/verify_release.sh` でいつでも再実行できます。アプリ内の「アップデートを確認」はダウンロードと検証のみを行い、手動インストールはこのメンテナ公開フローを実行しません。

固定起動パスとプロセスロックはこのバージョンおよび同じ仕組みを継承する以降のビルドを制約するものであり、この保護を持たない旧バージョンを別途ダウンロードして起動することまでは阻止できず、また macOS の別ユーザーアカウント間では排他制御を行いません。

具体的なテストケース、サポートマトリクス、および実機検証待ちの環境については [docs/testing.md](docs/testing.md) を参照してください。

## 技術的根拠

- [Apple FileManager.trashItem](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))：システムのゴミ箱を使用し、復元用の移動先 URL を記録します。
- [Apple コード署名に関するテクニカルノート TN2206](https://developer.apple.com/library/archive/technotes/tn2206/)：「`Current` が指していないバージョン」を無条件に削除可能なリソースと見なさない根拠です。
- [Playwright ブラウザのインストールとキャッシュ](https://playwright.dev/docs/browsers)・[公式レジストリ実装](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/registry/index.ts)：ブラウザ参照を照合し、未知の構造を保持します。
- [Swift Task](https://developer.apple.com/documentation/swift/task)：実行中のタスクを協調的にキャンセルし、処理完了を待ってから操作ロックを解除します。
